## 一、实习目的与意义

作为一名计算机科学与技术专业的学生，在大三课程结束后选择进入基层政务单位实习，我有三个明确的期待：一是把课堂上学到的软件工程、数据库、前后端开发等知识放到真实业务环境中检验；二是了解政府部门的政务数据管理是怎么运转的；三是接触人工智能（大语言模型）这一当前最热门的技术方向，看看它到底能在实际工作中解决什么问题。

围绕这三个期待，我在实习中给自己定了几个目标：理解政务公开与政务数据的基本特征；独立完成一个有真实数据、能真正跑起来的软件项目；把大语言模型工程化地接入项目中，而不是停留在"调 API 玩一玩"的层面；最后，把整个实习过程沉淀成可交付的成果，包括系统、数据、文档和报告。

## 二、实习单位与岗位简介

### （一）单位概况

新宁县政务服务中心数据局是承担新宁县政务服务与政务数据管理职能的部门，主要负责政务公开、政务服务事项管理、政务数据资源的归集与开放等工作。政务公开是法治政府建设的重要内容，政府门户网站的信息公开目录是公众获取政府信息的主要渠道。这类数据数量大、类目多、更新持续，怎么对它做高效、规范的分析利用，是数据管理工作里值得探索的方向，也是我这次实习的切入点。

### （二）岗位职责

我的实习岗位是数据分析实习生。实习期间单位没有安排固定的业务执行任务，我根据单位政务数据管理的工作方向，主动规划并完成了"数据采集 → 数据治理 → 数据分析 → 分析工具开发"的完整实践：一方面用爬虫技术采集、清洗政务公开数据并做统计分析；另一方面开发了一款面向政务场景的自然语言数据分析平台，让不懂 SQL 的业务人员也能直接提问、直接拿到图表和报告。

## 三、实习内容与过程

整个实习按时间大致分为五个阶段，下面按阶段说明我做了什么、怎么做的。

### （一）第一阶段（7 月 15 日—7 月下旬）：熟悉环境，确定方向

实习头两周，我主要做了三件事：一是熟悉单位职能和政务公开业务的运作方式，了解政府网站信息公开目录的结构与数据特征；二是搭建开发环境，确定技术路线——后端采用 Java 21 + Spring Boot 3 + MyBatis，前端采用 Vue 3 + Vite + Element Plus + ECharts，数据库使用 MySQL，AI 部分接入 DeepSeek 大模型；三是确定实习主线：以邵阳市政府门户网站依法公开的信息数据为研究对象，开发一个"自然语言驱动的智能数据分析平台"，让用户输入一句话就能自动完成数据分析并得到图表、解读和报告。

### （二）第二阶段（7 月下旬—8 月上旬）：AI 数据分析平台的设计与开发

这是实习的核心工作量所在。我把平台拆成一条完整的分析链路：意图识别 → 分析计划 → Text-to-SQL 生成 → SQL 安全校验 → 受控执行 → 图表推荐 → AI 数据解读 → 推荐追问 → 分析报告，每一步的过程都落库可回溯。

**1. 后端开发（Spring Boot 3 + MyBatis + JWT + 大模型接入）**

- 用户认证与权限：注册、登录、JWT 鉴权、个人资料、密码修改，用 Spring Security 统一处理未登录（401）和无权限（403）的情况；
- AI 分析引擎：
  - 意图识别：根据用户自然语言输入判断分析意图（趋势、排名、占比等），规则关键词与大模型双路识别；
  - Text-to-SQL：把自然语言问题转换成 SQL，生成前把表结构、字段语义、指标口径注入提示词，让生成的 SQL 贴合真实业务口径；
  - SQL 安全校验：内置 9 条硬性校验规则（禁止危险语句、限制影响行数、只允许白名单表等），校验不过直接返回 422 并附原因，杜绝"AI 乱写 SQL"的风险；
  - 受控执行与纠错：只执行通过校验的只读查询，SQL 执行报错时自动纠错重试；
  - AI 解读与报告：对查询结果生成自然语言解读、推荐追问问题、一键生成分析报告，全部采用"大模型优先、规则模板兜底"的三级降级策略，没有 API 密钥时平台照常可用；
- 会话与步骤追踪：每次分析按会话归档，9 个步骤的输入、输出、耗时、状态全部落库，同一会话重复分析采用覆盖式管理，避免数据膨胀；
- 管理端接口：数据源管理（增删改查 + JDBC 连接测试）、数据元配置（数据集/数据表/字段语义/指标口径）、数据分类管理，仅管理员可访问。

**2. 前端开发（Vue 3 + Vite + Element Plus + ECharts）**

- 分析页：自然语言输入 → 意图与计划展示 → SQL 展示 → 结果表格与 ECharts 图表 → AI 解读卡片 → 推荐追问按钮 → 报告卡片（支持复制与下载 Markdown），整个交互链路闭环；
- 认证与个人中心页面：注册、登录、资料维护、密码修改；
- 管理后台：数据源管理、数据元配置、数据分类管理界面，带权限控制。

**3. 测试保障**

项目建立了 L1 单元测试、L2 集成测试、L3 端到端验收测试三层测试体系，覆盖认证、分析流程、政务用例、管理后台等场景，后端全量测试 248 项全部通过，并完成了真实大模型链路的端到端验证。我在这部分最大的体会是：编译通过不等于功能正常，测试是让系统"敢给别人用"的前提。

### （三）第三阶段（8 月上旬）：政务数据采集与治理

有了平台，还要有真实数据。我针对邵阳市政府门户网站信息公开目录开发了爬虫，支持分页自动发现、栏目树解析、噪音过滤、幂等复跑（重复运行不产生重复数据）。对采集结果做了系统性治理：去重、空标题过滤、栏目壳页与导航噪音清理、日期规范化、发文单位三级补齐。

最终形成了 **3890 条规范化政务公开记录**（0 重复、0 空标题），覆盖约 45 个公开类目、2017—2026 年时间跨度；随后又针对"统计月报、统计公报、统计分析"三类统计栏目做了结构化管道，从 478 条公开内容中抽取整理出"期间 × 指标 × 区县"的结构化指标库，支撑平台做趋势、对比、排名类分析。
