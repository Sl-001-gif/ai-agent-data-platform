## 一、实习目的与意义

作为一名计算机科学与技术专业的学生，我选择在暑期进入基层政务单位实习，主要有三个目的：一是把课堂上学到的软件工程、数据库、前后端开发等知识放到真实环境中检验，看看「书上的系统」和「要真正跑起来的东西」差在哪里；二是了解政府部门政务数据的产生、归集与公开过程，认识真实业务数据的形态；三是接触大语言模型这一前沿技术方向，验证它到底能在数据分析中解决什么问题、又存在哪些局限。

围绕这三个目的，我在实习开始前给自己定了几个可检验的目标：理解政务公开数据的结构与特征；独立完成一个基于真实数据、可运行的软件项目；把大语言模型以工程化的方式接入项目，而不是停留在「调 API 玩一玩」的层面；最后把过程沉淀为可交付成果，包括系统、数据、文档和报告。

## 三、实习内容与过程

整个实习约一个月，按内容与里程碑分为五个阶段。

### （一）第一阶段（7 月 15 日—7 月下旬）：熟悉环境，确定方向

到岗后，我首先了解单位职能、政务公开业务流程以及政府网站信息公开目录的结构与数据特征；随后搭建开发环境并确定技术路线：后端采用 Java 21 + Spring Boot 3 + MyBatis，前端采用 Vue 3 + Vite + Element Plus + ECharts，数据库使用 MySQL，大模型接入 DeepSeek。在此基础上确定实习主线：以政府门户网站依法公开的政务数据为研究对象，开发一个「自然语言驱动的智能数据分析平台」，用户输入一句话即可自动完成从意图识别到报告生成的分析流程。

### （二）第二阶段（7 月下旬—8 月上旬）：数据分析平台的设计与开发（核心工作量）

这是实习工作量最大的阶段。我把平台拆成一条可追踪的分析链路：意图识别 → 分析计划 → Text-to-SQL 生成 → SQL 安全校验 → 受控执行 → 图表推荐 → AI 数据解读 → 推荐追问 → 分析报告，每个步骤的输入输出、耗时、状态都落库可回溯。

**1. 后端开发（Spring Boot 3 + MyBatis + JWT + 大模型接入）**
- 认证与权限：注册、登录、JWT 鉴权、个人资料、密码修改；用 Spring Security 统一处理未登录（401）与无权限（403），并修复了未登录访问接口返回空 403 等鉴权问题；
- AI 分析引擎：
  - 意图识别：规则关键词与大模型双路识别趋势、排名、占比等分析意图；
  - Text-to-SQL：生成 SQL 前把表结构、字段语义、指标口径注入提示词，让生成的 SQL 贴合真实业务口径；
  - SQL 安全校验：内置 9 条硬性校验规则（禁止危险语句、限制影响行数、只允许白名单表等），校验不通过直接返回 422 并附原因，杜绝 AI 乱写 SQL 的风险；
  - 受控执行与纠错：只执行通过校验的只读查询，SQL 执行报错时由大模型自动纠错重试；
  - AI 解读与报告：对查询结果生成自然语言解读、推荐追问问题并一键生成分析报告，采用「大模型优先、规则模板兜底」的三级降级策略，没有 API 密钥时平台照常可用；
- 会话与步骤追踪：每次分析按会话归档，同一会话重复分析采用覆盖式管理，避免数据膨胀；
- 管理端接口：数据源管理（增删改查 + JDBC 连接测试）、数据元配置（数据集/数据表/字段语义/指标口径）、数据分类管理，仅管理员可访问。

**2. 前端开发（Vue 3 + Vite + Element Plus + ECharts）**

- 分析页：自然语言提问 → 意图与计划展示 → SQL 展示 → 结果表格与 ECharts 图表 → AI 解读卡片 → 推荐追问按钮 → 报告卡片（复制/下载），整个交互链路闭环；
- 认证与个人中心：注册、登录、资料维护、密码修改；
- 管理后台：数据源管理、数据元配置、数据分类管理界面，带权限控制。

**3. 测试与质量保障**

项目建立了 L1 单元测试、L2 集成测试、L3 端到端验收测试三层测试体系，覆盖认证、分析流程、政务用例、管理后台等场景，后端全量测试 248 项全部通过。我坚持「测试先行、变更必补测」，每次功能变更都先写测试计划再实现，这让我深刻体会到「编译通过不等于功能正常」。

**4. 过程中解决的典型问题**

- 大模型分析结果与平台对接时，发现分析步骤的输出被硬截断为 5000 字符，导致大数据量分析结果反序列化失败、报告接口报 422「执行数据不完整」；排查后把存储上限提高到 60000 字符并改为 JSON 合法截断（在完整对象边界回退），问题解决；
- 部分大模型平台只允许 temperature=1，传 0.2 直接返回 400，通过按模型名区分参数处理解决；
- 早期接口鉴权、参数校验失败返回空 body 等问题，通过统一全局异常处理与鉴权入口修复。

### （三）第三阶段（8 月上旬）：政务数据采集与治理

有了平台还要有真实数据。针对邵阳市政府门户网站信息公开目录，我开发了爬虫，支持栏目树解析、分页自动发现、噪音过滤、幂等复跑（重复运行不产生重复数据）；随后对采集结果做系统性治理：去重、空标题过滤、栏目壳页与导航噪音清理、日期规范化、发文单位三级补齐。

最终形成 **3890 条规范化政务公开记录**（0 重复、0 空标题），覆盖约 45 个公开类目、2017—2026 年时间跨度；之后又针对「统计月报、统计公报、统计分析」三类统计栏目构建结构化管道，从 478 条公开内容中抽取整理出「期间 × 指标 × 区县」的结构化指标库，支撑平台做趋势、对比、排名类分析。
